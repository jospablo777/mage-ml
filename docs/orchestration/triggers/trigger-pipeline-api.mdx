## Configuring trigger type

When you create a new trigger or edit an existing one, choose the option `API`
under trigger type.

---

## API endpoint

The endpoint to use when making an API request will depend on the domain you’re
running MageML, the trigger’s unique ID and the trigger's token.

For example, if you’re running MageML on localhost with port 6789 and the trigger
you just created has an ID of 3 and the token `abc123`, then the API endpoint you’ll use is:

```
POST http://localhost:6789/api/pipeline_schedules/3/pipeline_runs/abc123
```

The trigger's detail page shows its full endpoint URL with the token.

---

## Request payload

You can optionally include runtime variables in your request payload. These
runtime variables are accessible from within each pipeline block.

### Example

```json
{
  "pipeline_run": {
    "variables": {
      "target": "staging",
      "schema": "public"
    }
  }
}
```

Or

```json
{
  "target": "staging",
  "schema": "public"
}
```

When the pipeline is triggered by this API request, each block in the pipeline
can access all the values defined in the variables object (e.g. `target`, `schema`)
within the request payload (in addition to the global variables defined within
the pipeline itself).

To use those runtime variables, use the variable name as a key when accessing
the keyword arguments dictionary (`kwargs`) in the decorated function of your
block. For example:

```python
@data_loader
def load_data(**kwargs) -> DataFrame:
    target = kwargs['target']
    schema = kwargs['schema']

    # ...other code
```

A body that is not a JSON object, such as the list of events HubSpot webhooks send, reaches
the blocks as `kwargs['body']` (also `kwargs['event']['body']`). A body that is not JSON is
refused with a 400 error that gives the reason.

You can include as many key value pairs within the variables object in the
request payload as you want. Do not use `env` as a variable name: pipeline runs always set
it to `prod`.

---

## Sample cURL command

Here is a sample cURL command using the examples listed above:

```bash
curl -X POST http://localhost:6789/api/pipeline_schedules/3/pipeline_runs/abc123 \
  --header 'Content-Type: application/json' \
  --data '
{
  "pipeline_run": {
    "variables": {
      "target": "staging",
      "schema": "public"
    }
  }
}'
```
