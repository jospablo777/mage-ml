MageML is a platform for building, running and shipping data and machine learning
pipelines. It is based on [Mage](https://github.com/mage-ai/mage-ai) 0.9.79 and runs on
Python 3.12 with pandas 3, Polars 2 and pyarrow 26.

Each step of a pipeline is a block: a file of Python, SQL, R or Rust that you run and
inspect in the editor, then schedule. In production, chains of blocks run together and
compile: consecutive Rust blocks become one optimized program and consecutive R blocks share
one R session.

## What MageML adds

| | |
| --- | --- |
| [Rust blocks](/guides/blocks/rust-blocks) | Loaders, transformers and exporters in Rust with Polars, compiled per chain. |
| [R blocks](/guides/blocks/r-blocks) | dplyr and tidyverse blocks with a pinned environment (rv). |
| [Compiled pipelines](/design/data-pipeline-management#pipeline-compilation) | Production runs fuse and compile chains of blocks; MageML checks and builds them ahead of the run. |
| [Pipeline services](/production/pipeline-services) | Export pipelines as a container that runs them without Mage, with an HTTP API and schedules. |
| [Pipeline performance](/production/pipeline-performance) | Benchmarks of pandas, Polars, R and Rust pipelines, and how to make yours fast. |
| [Data contracts](/guides/blocks/data-contracts) | Schema and value rules a block's output must meet. |
| [Run records](/guides/pipelines/run-records) | What each run used, compared and reproduced. |
| [Experiments](/guides/pipelines/experiments) and [model releases](/guides/pipelines/model-releases) | MLflow runs linked to pipeline runs, and checks before a model version is promoted. |
| [Monitoring](/guides/pipelines/monitoring) | Drift, missing values, row counts and freshness of block outputs. |
| [Pipeline environments](/guides/pipelines/pipeline-environments) and [resources](/guides/pipelines/resources) | Packages per pipeline, and CPU, memory and GPU limits per block. |
| [Feast features](/guides/blocks/feast-features) | Read and write features in a Feast feature server with values kept exact. |
| [ColumnAtlas](/design/column-atlas) | Explore a block's output: profiles and charts over the whole dataset. |

The [release notes](https://github.com/jospablo777/mage-ml/blob/master/docs/development/release-notes.md)
list every change from Mage 0.9.79, including the fixes to values Mage changed or lost
without an error.

## 🏔️ [Core design principles](/design/core-design-principles)

Every user experience and technical design decision adheres to these principles.

|     |                                                                                                           |                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 💻 | [Easy developer experience](/design/core-design-principles#easy-developer-experience)                     | Open-source engine that comes with a custom notebook UI for building data pipelines.                                         |
| 🚢 | [Engineering best practices](/design/core-design-principles#engineering-best-practices-built-in) | Build and deploy data pipelines using modular code. No more writing throwaway code or trying to turn notebooks into scripts. |
| 💳 | [Data as a first-class citizen](/design/core-design-principles#data-is-a-first-class-citizen)             | Designed from the ground up specifically for running data-intensive workflows.                                               |
| 🪐 | [Scaling made simple](/design/core-design-principles#scaling-is-made-simple)                           | Analyze and process large data quickly for rapid iteration.                                                                  |

## 🛸 [Core abstractions](/design/core-abstractions)

These are the fundamental concepts that Mage uses to operate.
|          |                                                        |                                                                                                                                                             |
| -------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🏢      | [Project](/design/core-abstractions#project)           | Like a repository on GitHub; this is where you write all your code.                                                                                         |
| 🪈      | [Pipeline](/design/core-abstractions#pipeline)         | Contains references to all the blocks of code you want to run, charts for visualizing data, and organizes the dependency between each block of code.        |
| 🧱      | [Block](/design/core-abstractions#block)               | A file with code that can be executed independently or within a pipeline.                                                                                   |
| 🤓      | [Data product](/design/core-abstractions#data-product) | Every block produces data after it's been executed. These are called data products in Mage.                                                                 |
| ⏰        | [Trigger](/design/core-abstractions#trigger)           | A set of instructions that determine when or how a pipeline should run.                                                                                     |
| 🏃‍♂️ | [Run](/design/core-abstractions#run)                   | Stores information about when it was started, its status, when it was completed, any runtime variables used in the execution of the pipeline or block, etc. |
