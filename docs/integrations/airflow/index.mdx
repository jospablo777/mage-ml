The recommended way: export the pipelines as a [MageML service](/production/pipeline-services)
and run them from Airflow with `MageMLServiceRunOperator`. The pipeline runs in the
service, with its own packages, block chains and compiled Rust and R, and Airflow
schedules it, retries it and shows its log. Airflow and MageML never share a Python
environment, so their packages cannot clash.

## Run a service's pipeline from a DAG

1. Install the provider in Airflow (Airflow 3, or 2.10):

   ```bash
   uv pip install "mageml-airflow @ git+https://github.com/jospablo777/mage-ml#subdirectory=packages/mageml-airflow"
   ```

2. Add a connection of type **MageML service**: the service URL as its host and the
   service token (`MAGE_SERVICE_TOKEN`) as its password. As an environment variable:

   ```bash
   export AIRFLOW_CONN_MAGEML_DEFAULT='{"conn_type": "mageml_service", "host": "http://shop-live.internal:8080", "password": "..."}'
   ```

3. Use the operator:

   ```python
   from airflow.sdk import DAG
   from mageml_airflow.operators import MageMLServiceRunOperator

   with DAG('nightly_scores', schedule='@daily'):
       MageMLServiceRunOperator(
           task_id='score_orders',
           pipeline='score_orders',
           variables={'day': '{{ ds }}'},
           output_block='summary',
           deferrable=True,
       )
   ```

| | What it does |
| --- | --- |
| Retries | Every try of a task instance sends the same idempotency key: a retry after a worker died finds the run still going instead of starting a second one; after a failed or cancelled run, the service starts a new one |
| Logs | The run's log lines go to the task log as they come, each with its block |
| Failures | A failed run fails the task with the failing block and its error |
| Outputs | `output_block` makes the block's output the task's return value (XCom), as JSON (a table as rows); an output over `output_max_bytes` (1 MB) becomes a reference to read it from the service |
| Waiting | `deferrable=True` waits in the triggerer and holds no worker slot; `poll_interval` sets how often it checks |
| Stopping | Clearing the task or marking it failed while it runs cancels the run |
| Variables | `variables` is templated, so `{{ ds }}` and other Airflow macros reach the run |

The provider's tests run it against a real service, and a DAG in Airflow 3.3 through
`airflow dags test`.

## Run a pipeline on a MageML server

For pipelines that are not exported as a service, `MageMLPipelineOperator` runs them on a
MageML server (the app) through its API. The pipeline runs on the server, as a run of its
API trigger named **Airflow**, which the operator makes when the pipeline has none.

1. Add a connection of type **MageML server**: the server URL as its host, and the email
   and password of a user with the editor role as its login and password:

   ```bash
   export AIRFLOW_CONN_MAGEML_SERVER_DEFAULT='{"conn_type": "mageml_server", "host": "http://mageml.internal:6789", "login": "airflow@example.com", "password": "..."}'
   ```

2. Use the operator:

   ```python
   from airflow.sdk import DAG
   from mageml_airflow.operators import MageMLPipelineOperator

   with DAG('nightly_report', schedule='@daily'):
       MageMLPipelineOperator(
           task_id='orders_report',
           pipeline='orders_report',
           variables={'day': '{{ ds }}'},
       )
   ```

| | What it does |
| --- | --- |
| Retries | The run carries the task instance's key in its variables (`mageml_airflow_key`): a retry finds the run while it runs or once it completed; after a failed or cancelled run it starts a new one |
| Logs | When the run ends, its blocks' log lines go to the task log, each with its block |
| Failures | A failed or cancelled run fails the task and names its failed blocks |
| Stopping | Clearing the task or marking it failed while it runs cancels the run |

A service is the better choice when you can export one: its runs start faster, retries
use idempotency keys the service enforces, and outputs come back as XCom.

## Run MageML inside Airflow's Python

The methods below run MageML in Airflow's own environment. MageML needs Python 3.12 and
its own package versions (pandas 3 among them), which often clash with Airflow's; each
block becomes its own task, without block chains or compiled Rust and R; and the workers
need a shared `variables_dir`. Prefer the service path above.

* First install MageML in the Airflow environment by adding `-r https://jospablo777.github.io/mage-ml/install/v0.2.0/base.txt` to your requirements.txt file (MageML needs Python 3.12).
* Then download the MageML project code into your Airflow directory, for example with a git submodule.
* In your MageML project's metadata.yaml file, please specify a variables_dir that you want to store the output of each block execution (You need to have write permission to the variables_dir). Example: `variables_dir: /tmp`.

There are multiple ways to run MageML pipelines in Airflow.
- [Create DAGs for all the pipelines in a project](#create-dags-for-all-the-pipelines-in-a-project)
- [Run pipeline in a BashOperator](#run-pipeline-in-a-bashoperator)
- [Run pipeline in a PythonOperator](#run-pipeline-in-a-pythonoperator)
- [Run pipeline as an Airflow DAG](#run-pipeline-as-an-airflow-dag)

For help with an existing Airflow project, see this
[tutorial](/integrations/airflow/integrate-mage-airflow) or ask in
[GitHub issues](https://github.com/jospablo777/mage-ml/issues).


## Create DAGs for all the pipelines in a project
```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime
from mage_ai.orchestration.airflow import create_dags
import os
ABSOLUTE_PATH = os.path.abspath(os.path.dirname(__file__))
project_path = os.path.join(ABSOLUTE_PATH, 'project_path')
create_dags(
    project_path,
    DAG,
    PythonOperator,
    blacklist_pipelines=[],     # Blacklisted pipeline uuids
    dag_settings=dict(
        start_date=datetime(2022, 8, 2),
    ),
    globals_dict=globals(),
)
```


<Note>
  These examples use the Airflow 2 API. `create_dags` passes `schedule_interval` to the DAG,
  which Airflow 3 removed.
</Note>

## Run pipeline in a BashOperator

Example code:
```python
from airflow import DAG
from airflow.operators.bash import BashOperator
from datetime import datetime
import os
ABSOLUTE_PATH = os.path.abspath(os.path.dirname(__file__))
project_path = os.path.join(ABSOLUTE_PATH, 'project_path')
pipeline_name = 'pipeline_name'
dag = DAG(
    'test_mage_pipeline',
    start_date=datetime(2022, 7, 14),
    description='Test running mage pipeline.',
    schedule_interval='@once',
    catchup=False,
)
task = BashOperator(
    dag=dag,
    task_id='run_pipeline',
    bash_command=f'mage run {project_path} {pipeline_name}',
)
```

## Run pipeline in a PythonOperator

Example code:

```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime
import mage_ai
import os
ABSOLUTE_PATH = os.path.abspath(os.path.dirname(__file__))
project_path = os.path.join(ABSOLUTE_PATH, 'project_path')
pipeline_name = 'pipeline_name'
dag = DAG(
    'test_mage_pipeline',
    start_date=datetime(2022, 7, 14),
    description='Test running mage pipeline.',
    schedule_interval='@once',
    catchup=False,
)
def build_execute_pipeline(project_path, pipeline_name):
    def _callable(ds, **kwargs):
        mage_ai.run(pipeline_name, project_path)
    return _callable
task = PythonOperator(
    dag=dag,
    task_id='run_pipeline',
    python_callable=build_execute_pipeline(project_path, pipeline_name),
)
```

## Run pipeline as an Airflow DAG

Example code:
```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime
from mage_ai.data_preparation.models.pipeline import Pipeline
from mage_ai.shared.hash import ignore_keys
import mage_ai
import os
ABSOLUTE_PATH = os.path.abspath(os.path.dirname(__file__))
project_path = os.path.join(ABSOLUTE_PATH, 'project_path')
pipeline_name = 'pipeline_name'
dag = DAG(
    'test_mage_pipeline',
    start_date=datetime(2022, 7, 14),
    description='Test running mage pipeline.',
    schedule_interval='@once',
    catchup=False,
)
pipeline = Pipeline(pipeline_name, repo_path=project_path)
tasks = []
def build_execute_block(block):
    def _callable(ds, **kwargs):
        mage_ai.run(
            pipeline_name,
            project_path=project_path,
            block_uuid=block.uuid,
        )
    return _callable
for uuid, b in pipeline.blocks_by_uuid.items():
    if b.type == 'scratchpad':
        continue
    tasks.append(dict(
        task_id=uuid,
        upstream_task_ids=b.upstream_block_uuids,
        python_callable=build_execute_block(b),
    ))
def initialize_tasks(dag, tasks):
    operators = {}
    for task_dict in tasks:
        task_operator = PythonOperator(dag=dag, **ignore_keys(task_dict, [
            'upstream_task_ids',
        ]))
        operators[task_operator.task_id] = task_operator
    for task_dict in tasks:
        for task_id in task_dict.get('upstream_task_ids', []):
            dag.set_dependency(task_id, task_dict['task_id'])
    return operators
initialize_tasks(dag, tasks)
```
