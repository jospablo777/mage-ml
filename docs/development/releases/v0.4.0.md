Python workers are now something you manage in the app. A block can run in a Python
environment of its own, so Feast with pandas 2, an MLflow 2 model next to MLflow 3, or any
SDK whose versions clash with MageML's runs in the same pipeline as MageML's own blocks.

## Workers

- **The Workers page**, in the left navigation: create a worker from a template, type its
  packages as you would in `pyproject.toml`, pick versions from the package index and the
  Python it runs on, edit its `pyproject.toml`, check it for vulnerabilities and fix them,
  rename or delete it. **MageML (default)** heads the list: MageML's own Python, with the
  uv command that changes it.
- **Nothing breaks on save.** Every change is locked by uv in a copy first. Versions that
  cannot go together are refused in one sentence: `feast 0.68.0 needs pandas>=1.4.3,<3,
  and the worker lists pandas==3.1.1`. When uv would fall back to an old release of a
  package you gave no version (Feast 0.20.0 from 2022, whose `pandas>=1` allows pandas 3),
  the page asks first; a package already held back shows why.
- **Fast.** Blocks in a worker run in warm processes: 5 ms per block instead of 228 ms,
  twenty small blocks in 1.6 s instead of 3.4 s. Each block still starts as in a new
  process: changed project files are imported again, and what a block did to `os.environ`
  or `sys.path` is undone.
- **Safe.** A memory limit per worker; MageML's credentials never reach a worker; one
  worker whose files cannot be read shows as broken and leaves the others working.
- **Every Python block says where it runs** and changes it in one click.
- **Tested with what workers are for**: Feast, MLflow 2 and MLflow 3 in one pipeline, HTTP
  APIs, diamonds, a chain that changes worker at every block, and blocks of several
  pipelines at once.
- The worker protocol is written down, with a conformance suite another implementation can
  run.

## Services

- An exported service builds each worker into the image, on its own Python when it needs
  another, and workers that resolve to the same versions become one environment.
- **Image size**: after a build, the Services page shows the image as one bar of its parts
  (base image, Python packages, each worker, the MageML runtime, models, project code)
  next to the build before; the build commands print the same.
- **Reproducible exports**: with `SOURCE_DATE_EPOCH` set, the same sources give the same
  zip, byte for byte.
- Kafka streams read at full speed again: 578,000 messages a second through a Python block
  and 909,000 through a Rust block (0.3.0: 250,000 for both).

## Fixes

- A finished run no longer shows as running: a read-only API request left its database
  transaction open.
- R blocks read their input tables into R's own memory; a list column could hold garbage
  by the time the output was written.
- lettre 0.11.24 in the engine fixes six advisories.

## Before upgrading

Check the behavior changes in the
[release notes](https://github.com/jospablo777/mage-ml/blob/master/docs-md/development/release-notes.md):
a worker is named by its folder (`python_workers/<name>/`), not its project's name, and
blocks that used the old name still find it; a worker without `.python-version` runs on the
closest Python its `requires-python` allows; consecutive Rust blocks with different
connection profiles no longer compile into one chain.

`mage-integrations` 0.2.0, `column-atlas-native` 0.2.1, `mageml-engine` 0.2.1 and
`singer-python` `5.13.0+mage.2` are unchanged, and the index keeps their published wheels.

## Install or upgrade

```bash
uv add "mage-ml==0.4.0" mageml-engine --index mageml=https://jospablo777.github.io/mage-ml/simple/
```

In a project that already has MageML: `uv lock --upgrade-package mage-ml && uv sync`. With
pip: `python -m pip install -r https://jospablo777.github.io/mage-ml/install/v0.4.0/base.txt`.
All the ways to install are in the
[Quickstart](https://github.com/jospablo777/mage-ml/blob/master/docs-md/getting-started/setup.md).

Wheels are qualified on Linux x86-64 and ARM64 (glibc 2.28 or newer) and macOS Apple
Silicon (macOS 12 or newer), with CPython 3.12.
