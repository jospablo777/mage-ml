Streaming pipelines run as services on a Rust engine, and you build them in the editor on
real messages without touching production. Services, batch or streaming, are code in your
repository, deployed to Docker, Kubernetes or IBM Cloud Code Engine with a lock that pins
what was built.

## Stream services

- **Sources**: Kafka (also Azure Event Hubs and IBM Event Streams), webhooks, RabbitMQ, NATS
  JetStream, IBM MQ, ActiveMQ, Amazon SQS, Google Cloud Pub/Sub, MongoDB change streams and
  PostgreSQL changes by logical replication. **Sinks**: those that write, plus PostgreSQL,
  ClickHouse, Elasticsearch and OpenSearch, InfluxDB, object storage, HTTP and Feast.
- **At least once everywhere**: a source's position moves only after every sink took the
  batch, and a message a block fails on goes to a dead-letter sink with its error. Tested,
  with no message lost, through broker restarts, a broker down past the session timeout,
  network partitions, `kill -9` of the engine and a failing or slow sink.
- **Blocks in Python, Rust or R**, mixed in one chain. Kafka to Kafka through one block on
  a laptop: about a million messages a second with a Rust block, 586,000 with Python.

## Streams in the editor

- **Samples**: capture the newest messages of a source without moving any consumer, and
  **Run on sample** runs a block and the blocks before it at once, showing what it changed.
- **Run** tab: the stream on the local engine with a development consumer group (or slot),
  so production's position never moves; it asks before writing to real sinks, and shows
  rates, lag, per-block numbers and the messages at any block.
- **Dead letters** tab: read them, open them as a sample to reproduce the failure, and replay
  them once the block is fixed.
- Templates per source, the stream's plan in the Compile panel, seven runnable examples
  (`mage examples streams`), two tutorials, and stream pipelines in the playground
  (`make playground-streams`).

## Services as code

- `services/<name>/service.yaml` with environments, and `service.lock` pinning the
  manifest, files, requirements, models and engine. `mage service run` runs a service on
  this machine without Docker.
- `mage service deploy`, `status`, `diff` and `rollback` for Docker, Kubernetes and IBM
  Cloud Code Engine: health waits with automatic rollback, drift from the repository,
  promotion between environments, and a GitHub Actions workflow from `mage service ci`.
- A deploy stops on what should not ship: uncommitted inputs, an output schema change that
  breaks its readers, or a failing sample test, unless a recorded reason says otherwise.

## Before upgrading

Check the behavior changes in the
[release notes](https://github.com/jospablo777/mage-ml/blob/master/docs-md/development/release-notes.md),
among them: editor stream runs no longer move production's consumer group; services move
from `pipeline_services.yaml` to `services/<name>/` (`mage service migrate`); service blocks
start from an empty environment; SQL loaders mask string literals in the queries they log
(`MAGE_LOG_QUERY_VALUES=on` shows them); a block downstream of several children of one
dynamic block pairs their items instead of running once per combination.

`column-atlas-native` and `mage-integrations` stay 0.1.1 and `singer-python`
`5.13.0+mage.2`, unchanged; the index keeps their published wheels. The stream engine is
the new `mageml-engine` 0.1.0 wheel.

## Install or upgrade

```bash
uv add "mage-ml==0.2.0" mageml-engine --index mageml=https://jospablo777.github.io/mage-ml/simple/
```

`mageml-engine` runs streams and services on this machine (`mage service run`, the editor's
Run tab); leave it out if you only run batch pipelines. In a project that already has
MageML: `uv lock --upgrade-package mage-ml && uv sync`. With
pip: `python -m pip install -r https://jospablo777.github.io/mage-ml/install/v0.2.0/base.txt`.
All the ways to install are in the
[Quickstart](https://github.com/jospablo777/mage-ml/blob/master/docs-md/getting-started/setup.md).

Wheels are qualified on Linux x86-64 and ARM64 (glibc 2.28 or newer) and macOS Apple
Silicon (macOS 12 or newer), with CPython 3.12.
